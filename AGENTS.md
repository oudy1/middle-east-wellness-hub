- Keep volunteer response reads in the admin-authenticated `volunteer-sheet` Edge Function (Google Sheets credentials stay server-side), or from a CSV export the admin opens on `/admin/volunteers`, parsed in the browser only and never uploaded or stored, so volunteer details never land in the database.
- Public-submission tables accept anonymous inserts only through RLS policies with explicit length/format checks (never `WITH CHECK (true)`); intake tables no site form uses stay closed to the public, so they cannot be flooded.
- Public forms that send email pass `useSpamGuard` fields (hidden trap + fill time) to `send-contact-email`, which silently drops bot hits, applies a best-effort per-IP limit, and never returns provider error details to the browser.
- Admin access is granted only by the `grant_allowlisted_admin` trigger when a confirmed sign-in email matches the service-only `admin_email_allowlist`; add admins by inserting into that list, never from client code.
- Time-limited events (e.g. `src/lib/newcomerWorkshop.ts`) keep their date in one module and hide themselves by comparing the Toronto calendar date, so homepage and Programs never show a past event as upcoming.
- Every internal link the chatbot, its knowledge index or the header search can produce must be listed in `content/chatbot-routes.json` (mirrored in the `shams-chat` function); `chatbotSearch.test.ts` fails on any unlisted address, so invented or dead anchors cannot ship.
- Time-limited chatbot knowledge entries carry `activeUntil` (Toronto date) from the event's own module, so the assistant stops recommending an event after it ends.
- Site search and chatbot retrieval share `src/lib/searchText.ts` (Arabic normalization, length-based typos, prefix match) and the header/home finder uses `searchSite` in `src/lib/siteSearch.ts` (curated list + knowledge index, ranked by matched words), so both stay in step without a search server or paid service.
- Translations run on i18next (`src/i18n/index.ts`) behind the existing `useLanguage().t`, with flat keys in `content/translations/*.json` (keySeparator off); counts use `t(key, { count })` with `_one/_other` (+ Arabic `_zero/_two/_few/_many`), and `translations.test.ts` fails on missing Arabic text, missing plural forms or unknown keys, so gaps are caught before publishing.
- The language menu lists only `AVAILABLE_LANGUAGES` (languages with every English key translated), and a saved hidden language falls back to English, so half-translated languages never reach visitors and reappear on their own once complete.
- Every page except the homepage is loaded with `lazyWithRetry` in `App.tsx`, lower homepage sections sit inside `LazySection` (render when scrolled near, or at once when the URL has a #hash), and the chat window loads on first open; `tests/e2e/lazy-loading.spec.ts` guards this, so phones download only what they view and a stale file after publishing reloads once instead of breaking.
- Doctor listings are public only when `status = 'published'` (RLS); the `healthcare_workers_guard` trigger blocks visitors from setting any review field and moves applicant email/notes into admin-only `healthcare_worker_reviews`, `healthcare_workers_log` records history, and a partial unique index stops duplicate published listings, so unreviewed or private details never reach visitors (check: `supabase/tests/healthcare_worker_approval.sql`, `tests/e2e/directory-approval.spec.ts`).
